# 数据源与故障处理

## 主链路：东方财富

- 股票池：`https://push2.eastmoney.com/api/qt/clist/get`
- 日线：`https://push2his.eastmoney.com/api/qt/stock/kline/get`
- 创业板/科创板过滤：`fs=m:0+t:80,m:1+t:23`
- 日线默认 `klt=101&fqt=1`：前复权价格，成交额不复权。

必须按100条分页。即使请求 `pz=5000`，接口也可能只返回100条；若同时按涨幅排序，就会制造“候选全部大涨”的严重选择偏差。

校验：

1. `data.total` 等于分页拼接行数；
2. 股票代码去重后仍等于总数；
3. 涨跌幅覆盖负值、零附近和正值；
4. 不接受最低涨幅仍为约+5%的所谓完整股票池。

## 降级链路：新浪＋腾讯

- 新浪快照：`Market_Center.getHQNodeData`，节点 `cyb`、`kcb`
- 腾讯前复权日线：`appstock/app/fqkline/get`

新浪可能只返回有有效报价的股票，因此与主数据源总数存在停牌或口径差异。明确报告差额。

腾讯日线不提供成交额时，使用：

```text
成交额代理 = (开盘+最高+最低+收盘)/4 × 成交量
```

代理值只能用于同一股票内部的成交额比率，并必须在输出中披露；不可冒充精确成交额。

## 网络与限流

- 每次请求设置12—15秒超时；
- 指数退避重试，最多4—5次；
- 快照并发不超过2页，日线并发默认8—12只；
- 服务端断开连接时降低并发或切换数据源；
- 记录失败代码，不得静默剔除；
- 先以 `--limit 10` 冒烟测试，再运行完整池。

不要把旧缓存写成当日行情。使用缓存重跑时，在标题和数据口径中明确缓存日期。
